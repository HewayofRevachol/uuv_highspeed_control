## 1. MPC 基线和失效机制

### 1.1 组件消融定位了执行器失配

在四条耦合路径、每条 10 个种子的组件消融中，报告给出的严格完成数为：

| 条件 | 严格完成 | 相对源域 `29/40` 的含义 |
| --- | ---: | --- |
| 源域 | 29/40 | 名义模型的参考水平 |
| 仅谐波海流 | 29/40 | 该幅值下海流不是主要退化来源 |
| 仅舵效 `0.9` 倍 | 10/40 | 对舵效失配高度敏感 |
| 仅二阶执行器 | 11/40 | 对执行器动态失配高度敏感 |
| 舵效 + 二阶执行器 | 4/40 | 两种失配叠加后显著恶化 |
| 四项全变 | 4/40 | 海流/积分器变化没有掩盖主因 |

15 m/s 下 5° 方向舵阶跃的瞬时偏航加速度增益约为 `0.480 rad/s²/rad`，实际舵达到 90% 约需 `0.26 s`，偏航角速度达到最终响应 90% 约需 `11.42 s`、前进约 `170 m`。这说明 0.1 s 控制周期并不能消除长时间的执行器和艇体响应；MPC 若把舵效或延迟估得过于乐观，会在预测窗内过度信任尚未实现的响应。这些数字限于该阶跃条件，且历史基线曾另有末端参考截断问题；CAT 对照应共享已经修复的末端切线延拓。

### 1.2 固定保守模型是强确定性基线

冻结参数后，四条新的耦合路径 × 五个植物/扰动种子的留出结果为：

| 控制器 | 严格完成 | 路径分解 | 回退 | p95 中位数 | 最大回合 p99 |
| --- | ---: | --- | ---: | ---: | ---: |
| OSQP N20 | 0/20 | 0/0/0/0 | 0 | 30.4 ms | 44.2 ms |
| 原 condensed N35 | 0/20 | 0/0/0/0 | 9 | 52.1 ms | 118.2 ms |
| 保守 condensed N35（`0.85/2.0`） | 14/20 | 4/4/2/4 | 2 | 45.8 ms | 99.79 ms |

相对原 N35，保守模型在 20 个配对单元中改善 14 个、恶化 0 个，严格完成率提高 70 个百分点；非耦合回归为 `10/10` 对 `10/10`，没有看到明显回归。剩余失败按报告为：俯仰 2 次、航速 2 次、深度 1 次、求解失败 1 次。

这组结果的正确解释是“保守控制整形有效”，而不是“`.85/2.0` 已辨识出真实舵效和时间常数”。开发集的已知系数 oracle（约 `0.90/1.69`）只有 `2/5`，低于固定保守候选的 `4/5`；因此闭环性能与参数真值误差不能简单画等号。

一个待验证的机制是：预测器认为舵效较弱、响应较慢，会让优化器更早施舵或增加指令幅度，从而补偿未建模二阶动态、有限时域和线性化误差。这种“预测保守”不等于“控制动作更小”，也可能增加饱和、超调或 QP 负担，不能推论为舵效越低、时间常数越大越好。应在相同状态快照上分别测量施舵提前量、指令幅度、实际舵饱和、1/5/25 步误差及首次违约，才能判别收益来自预测更准、控制相位改变还是求解条件改善。

### 1.3 统计和实时性边界

`14/20` 的二项 Wilson 95% 区间约为 `48.1%–85.5%`，这是本次根据历史计数计算的描述性区间，未计入几何相关性。四条耦合几何各只有 5 个种子，跨几何泛化证据仍只有 4 个簇。`+14/-0` 在独立配对假设下的双侧精确 McNemar 检验为 `2/2^14≈0.000122`；该假设对共享几何的运行可能过强，不能将这个数当作已确立的泛化显著性。“0 次恶化”也不等于零风险。

最大回合 p99 `99.79 ms` 只比 100 ms 门槛低 `0.21 ms`，而且是 20 回合中的最大值。它应作为当前机器上的尾延迟诊断，不能当作硬实时保证。正式比较必须报告逐周期 p50/p95/p99/max，并在固定线程、无并行竞争、预热后的 batch=1 条件下复测。

## 2. 早期离散速度 RL 的验证解读

GS-10 的 Gate3 比较了固定速度基线、确定性治理器和 RL 治理器，文档记录为两个开发几何 × 三个种子、每种方法 `0/6 strict_mainline`。该数字不能直接推出“RL 无效”，原因如下。

与固定保守基线相同，Gate3 的逐周期 CSV、`summary.json` 和报告引用的输出目录没有随当前 checkout 提供；这里引用的是 `docs/GS-10_H15_RL_MPC_RESULT_ANALYSIS_AND_NEXT_MAINLINE_20261104.md` 与 quickstart 文档的历史转述，不能在本次工作区独立复算。

### 2.1 严格指标被结构性 deadline 标记污染

`experiments/h15_mainline/run_offline_governor_smoke.py` 在离线运行时固定传入 `deadline_missed=True`。因此即使轨迹到达终点且没有 0.02 s 子步物理违约，也会被 `strict_mainline` 排除。下一版至少应分开保存：

- `strict_hist`：历史严格口径；
- `physical_complete`：到达终点且没有子步物理违约；
- `no_intervention_complete`：再排除 fallback、backup 和空候选；
- `completed_with_backup`、首次违约、fallback 和实际逐周期 deadline。

离线比较可以使用 `physical_complete` 或 `no_intervention_complete` 诊断，但不能改名为在线严格成功。

### 2.2 备份和保持协议遮蔽了策略动作

一条 E1 配对回合中，199 个控制周期里约 171–173 个周期由备份接管，约占 86%；B2 仅有 3 个周期选择了 14 m/s，进度和最大速度误差与固定基线相同。这说明困难回合的大部分闭环行为由共同的固定 15 m/s 备份决定，策略很少获得能影响结果的动作机会。

此外，B0、B2、B3 都使用 `E1` 估计器，缺少同一配对链上的 `B0_E0 → B0_E1 → B2_E1 → B3_E1`；RL 每 0.5 s 决策，而确定性选择器可以每周期重选；旧 actor 最后一层全零初始化，初始策略在相同 mask 下会选择同一动作。上述因素使“RL 与基线相同”难以归因。

因此，Gate3 目前最多支持：在当前候选、保持和备份协议下没有观察到 RL 独立增益；它不能否定更合理的连续门控接口。

## 3. CAT-MPC 计划的机制与验证条件

CAT-MPC 的最小原型有清晰的研究问题：固定任务速度 15 m/s，历史适配器给出有效响应修正，因果残差预测器给出未来体加速度残差，PPO 每 0.5 s 输出 `alpha_theta` 和 `alpha_d`，MPC 每 0.1 s 重新线性化并只求解一次。点模型以固定保守模型为零点：

```text
f_point = f_(0.85,2.0)
          + alpha_theta * (f_theta_hat - f_(0.85,2.0))
          + B_d * alpha_d * d_hat
```

这一定义使 `(0,0)` 与现有强基线等价，避免把 RL 的收益错误归因给更换零点。计划还明确了 22 状态（艇体 10、实际控制量 3、三段命令队列 9）、因果历史窗口、raw Gaussian log-prob、slew 限幅、5 个 MPC 周期保持、0.02 s 子步审计以及 fallback/intervention 记录。

### 3.1 当前尚不能报告 CAT-MPC 的验证结果

在可见仓库中没有 CAT runner、checkpoint、`run.json`、逐周期日志或 `summary.json`。因此以下量均为缺失项，而不是零：

- A0–A4 固定门控的完成率和首个违约；
- PPO checkpoint 和不同策略种子的配对完成率；
- alpha 的分布、变化率、饱和率和 raw log-prob；
- predictor 的 1/5/25 步误差、覆盖率和区间宽度；
- fallback、backup、intervention 和全周期尾延迟。

拿到 `experiments/h15_cat_mpc` 或对应 commit 后，应先运行 P0 等价性检查，再读取 P1/P2/P3 的结果；在此之前不应把 CAT 计划中的探索门槛写成实测通过。

### 3.2 计划本身需要修正的地方

1. **历史留出不能重复称为未见。** `.85/2.0` 在原留出运行前已冻结，原来的留出结果不应因此被否定；但计划引用的 `h15_mpc_fix_holdout` 如今已被评估和反复分析，新算法若参考这些结果设计，复用它只能作为历史诊断。P3 应先冻结所有策略、阈值和 checkpoint，再生成真正未见的几何/植物/扰动留出。
2. **样本计数需统一。** P3 的方法数为 A0、最强确定性 gate、3 个 PPO 种子和 1 个标量策略，共 6 种方法；4 个未见几何 × 5 个种子是 20 个配对单元，因此应明确是 120 条方法轨迹，而不是 100。
3. **不确定度集合必须与点模型分开。** 现有 `response_estimator.py` 的 radius 是估计值到配置边界的距离，随后又被裁切回同一配置矩形；在范围内改变估计值不会形成真正收缩的四角集合。没有独立覆盖校准前，不能把它称为置信度收缩。
4. **修复一周期前视。** 现有校准脚本在使用当前行 `state_after` 后再从该行 `state_before` 回放；在线估计器只应使用已经完成的历史转移，当前周期的后状态只能在标签生成后进入下一周期。
5. **验证 alpha 真能改变闭环。** 若固定 `(0,0)`、`(1,0)`、`(0,1)`、`(1,1)` 只改变日志而不改变点模型、首条命令或后续余量，应停止 PPO，先修复残差映射或观测接口。

## 4. 建议的改进路线

### 4.1 先建立可审计的响应估计和不确定度

**优先检查当前门控动作空间是否覆盖有益偏置。** CAT 的 `alpha_theta` 只能在固定 `.85/2.0` 与估计器输出之间插值。如果估计器趋近真实参数，而真实参数对应的近似 MPC 闭环反而更差，最优策略可能长期选择 `alpha_theta≈0`；这不必然是 PPO 没训练好。先做开发集上的预测舵效 × 时间常数单因素/联合扫描，例如 `{.75,.85,.95,1.05}×{1,1.5,2,2.5}`，检查有效区间是否宽、是否随曲率/深度机动变化。这是离线机制扫描，不把网格变成 RL 离散动作集。

若收益来自稳定的控制偏置，可将“因果参数估计”和“策略调整的有界性能偏置”分开：固定估计器负责物理预测，策略在 `.85/2.0` 周围调节一个小范围连续偏置或代价权重；另一条支路维持独立的误差集合和约束。该方向需作为新消融，与原 CAT 插值、固定最优偏置、置信度规则逐项比较，不应直接替换后再把收益归给原算法。

把“预测中心”和“风险集合”拆成两个对象：

- 中心：固定保守模型、因果 RLS/EKF/MHE 或历史网络输出的 `theta_hat`；
- 集合：由独立 `dev_cal` 拟合、在 `dev_eval` 验证覆盖率的参数集合/残差管。

快速 P0–P3 可先冻结现有边界/约束接口，仅测试均值预测和连续门控，不等待正式集合校准。低激励、OOD 或估计器超时采用固定回退规则，并对所有方法一致应用。若后续引入置信度 gate 或集合收缩，才先完成独立校准，并把覆盖失败纳入回退；门控不能自行缩小风险集合、放宽状态约束或删除 fallback。预测器先报告 1/5/25 步中心误差，进入区间版本后再补覆盖率和区间宽度。若 AR/GRU 不优于 persistence，关闭残差支路、保留响应支路，且不扩展 diffusion；P08 的扩散 AUV-MPC 论文只能作为结构参考。

### 4.2 用配对反事实确认连续动作的机制价值

在相同快照、相同后续扰动和相同 MPC 预算下，令 `a∈{0,.25,.5,.75,1}`，分叉运行 `(alpha_theta,alpha_d)=(a,0)、(0,a)、(a,a)`，测量首条命令差异、1/5/25 步预测余量、首次物理违约、fallback/backup 以及恢复完成率。这是去重后 13 组低成本离线干预；只有发现耦合效应时才扩成 5×5 网格。该实验可以先不训练 RL，直接回答连续门控是否有可利用的控制敏感度。

固定门控之后再比较：

1. 固定保守模型（计划中的 A0）；
2. 只启用历史响应修正（A1）；
3. 只启用残差前馈（A2）；
4. 两支路全部启用（A3）及固定中间强度（A4）；
5. 置信度/余量规则 gate；
6. 二维 PPO，以及标量门控 `alpha_theta=alpha_d` 的消融。

这些编号沿用 11 月 5 日计划，A0–A4 都是固定门控，并不是 PPO。所有方法应共享约束、回退、保持周期、观测和计时口径。若规则 gate 已达到 PPO，停止增加 RL；若标量与二维策略相当，优先保留标量接口。

### 4.3 设计针对失效机制的压力测试

冻结策略后逐因素做配对压力测试：植物舵效倍率 `{0.8,1.0,1.2}`（`1.2` 超出当前估计器上界 `1.1`，单列为 OOD），执行器时间常数倍率 `{0.5,1,2}`，纯命令传输延迟则以现值为基准单独增加 `0/0.02/0.04 s`。时间常数和纯延迟不能混为一个参数；修改延迟时要重新验证队列语义。先分别测敏感性，再选两项有交互的因素做联合网格；随后加入中途参数突变、白噪声/相关扰动/谐波海流、低激励和高激励轨迹。单独比较一阶和二阶执行器状态，避免把 22 状态接口的信号写成已经精确建模了二阶 rate。

正式留出按几何簇汇总，不能把控制周期当独立样本。至少报告每种方法的改善/恶化配对数、首次违约类型和时刻、physical/no-intervention complete、fallback/backup、速度误差、路径误差和 p50/p95/p99/max。多策略种子全部纳入，不能只挑最佳 checkpoint。

### 4.4 增加安全和实时边界

短期采用固定约束集合、实际执行器/队列状态和经验恢复延续；如果要声称安全性，再单独建立可验证的误差界、终端安全集和可执行 backup。当前的一步固定 15 m/s backup 不是递归可行性证明。

实时性上，适配器、预测器、策略、MPC、积分和日志都计入完整 100 ms 周期。保守基线已经只有 0.21 ms 的最大 p99 余量，新增 GRU、扩散或 GPU 传输必须以串行 batch=1 的尾延迟重新测量；GPU batch 吞吐不能替代单艇控制延迟。

- [ ] **P0 等价性**：确认 CAT `(0,0)` 与保守 N35 的首命令、22 状态和轨迹在容差内一致；确认没有未来状态、每周期只求解一次 MPC。
- [ ] **P1 机制 screen**：冻结 adapter/predictor，运行 A0–A4 的配对快照和 dev 回合，记录 alpha 是否改变命令、余量和物理事件。
- [ ] **P2 单种子 pilot**：只在 P1 有信号时运行约 4,000 次门控决策；与固定 gate 共享相同噪声 tape，报告 checkpoint 曲线而非单点最好成绩。
- [ ] **P2 退出门**：4,000 决策后无收益且曲线无持续改善就停止。仅在六个 dev 配对单元中达到计划的一项探索门（至少 2 个失败变无干预完成且 0 个恶化；或完成持平、共同成功跟踪误差下降至少 10% 且时间增幅≤3%/速度误差不增；或完成和误差不恶化、干预比例下降至少 20% 且不由单回合独占）后进入 P3。这些是预算决策门，不是统计显著性。
- [ ] **P3 多种子真正留出**：P2 通过后，策略种子 `41001/41002/41003` 全部冻结，使用未读过的几何/植物/扰动组合，并按几何簇汇总。
- [ ] **P4 扩展**：只有 P3 稳定超过确定性 gate 后，才增加 25 状态、区间校准、蒸馏预测器、50 Hz telemetry 或 GPU MPC。

判定标准应保持三类结论：接口无效；连续门控有机制信号但 RL 无独立增益；RL 在相同信息、约束和预算下有初步配对优势。第三类只允许进入更严格验证，不构成安全证明或实艇泛化结论。
