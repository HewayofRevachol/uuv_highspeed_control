# H15 推荐主线详细实验规划

日期：2026-11-04

主线名称：**执行器响应不确定度条件下的参考进度速度治理 + 受限 RL + 执行器感知 MPC**。

主线的职责划分如下：

- 历史响应估计器从可部署观测中估计等效执行器/动力学响应及其不确定度。
- 确定性可行速度治理器检查参考进度计划经过 MPC 后是否有足够的状态、执行器和终端余量。
- MPC 继续产生推力、升降舵和方向舵命令，并承担短时动力学预测。
- RL 只在已经核验的候选参考进度计划中选择一个低频速度意图，不直接输出舵角残差，不替代硬约束。

本文件是实验执行清单，不是已经获得的实验结果。所有“通过”都必须由冻结后的日志、配置、代码哈希和配对轨迹证明。

## 文献方法在主线中的落点

- [ ] P04 RMA 的历史适应思想只用于 C 阶段的部署可得历史响应估计，并单独验证数据泄漏和 OOD 回退。
- [ ] P05 MPCC++ 的路径/进度联合建模用于 D 阶段的几何进度参考与终端延拓；不能替换 H15 的实际艇体对水速度指标。
- [ ] P06 HyperMPC 的历史与计划动作条件参数用于 E3 估计器对照；输出只称“时域等效参数”。
- [ ] P09 RL-guided MPC 的高层参考、低层 MPC 结构用于 E 阶段；RL 只选一个经过过滤的低频进度速度意图。
- [ ] P10 TD-MPC 的短窗规划/终端价值作为 Gov4 或 RL 的同预算候选选择对照，不得绕过硬约束。
- [ ] P11 Predictive Safety Filter 的备份轨迹和终端安全集用于 D/H 的空集、超时和恢复测试；没有闭合安全集时只写经验筛选。
- [ ] P13 Robust Adaptive MPC 的参数集合和 tube 收紧用于 C/D 的区间校准与不确定度收紧消融。
- [ ] P15 RTI 的有限迭代和实时优化用于 B 阶段；必须与 condensed 实现分别计时和报告。
- [ ] P16 AUV tube-MPC 的约束收紧与 LOS 重规划用于 D/F 的海洋场景对照，并标注适用假设。

## 0. 冻结任务、指标与退出规则

### 0.1 H15 任务合同

- [ ] 将任务配置复制为不可变版本：`aav_mpc/configs/h15.json`。
- [ ] 固定控制周期为 0.1 s，积分步长为 0.02 s，每周期 5 个积分子步。
- [ ] 固定名义任务速度为 15 m/s。
- [ ] 固定几何参考进度率范围为 13–17 m/s。
- [ ] 固定几何参考进度率变化率上限为 0.5 m/s²，即每个 0.1 s 周期最多变化 0.05 m/s。
- [ ] 固定 H15 严格阈值：横向误差 ±8 m、深度误差 ±5 m、俯仰角 ±40°、沿路径切向艇体对水速度相对 15 m/s 的误差 ±2 m/s。
- [ ] 定义并冻结 `strict_hist`：按原 H15 历史 0.1 s 口径、原终止和原 fallback 判定复现 14/20；历史字段只读，不能因新规则回写。
- [ ] 定义并冻结 `strict_mainline`：走完整条路径、全程不越界、通过 0.02 s 子步检查，且 MPC fallback、backup takeover、候选集为空、deadline miss 或物理违约都计为失败。
- [ ] 若经验证的备份轨迹仍能完成任务，另报 `completed_with_backup` 次级指标；不能把它静默计入 `strict_hist` 或 `strict_mainline`。
- [ ] 明确实际速度指标为 `tangent · R(theta, psi) · v_body`，不要用艇体速度模长替换原 H15 口径。
- [ ] 明确几何参考进度率、艇体对水速度、对地速度和路径弧长推进率是四个不同字段。
- [ ] 明确 0.02 s 子步原代码只有较宽松的终止保护；新增子步严格检查后，旧结果和新结果必须分开报告。

### 0.2 已知基线与验收门槛

- [ ] 将历史报告的 `B0_hist` 结果记录在 manifest 中：修复留出 14/20，6 个首次失败（2 俯仰、2 航速、1 深度、1 求解）。
- [ ] 将 `B0_hist` 的历史计时记录为上下文：p95 中位数 45.84 ms、最大回合 p99 99.79 ms。
- [ ] 明确 99.79 ms 只是当前机器和当前实现的统计结果，不是硬实时证明，也不为新模块预留预算；为在线候选主线预注册工程余量（例如完整周期 p99 ≤90 ms、最大值 ≤100 ms、策略/估计器/过滤总开销 ≤5 ms）。
- [ ] 预先注册实用收益关注阈值：严格完成率至少改善 10 个百分点；同时报告置信区间和改善/恶化配对数。
- [ ] 预先注册停止规则：若确定性底座已经达到目标，停止增加 RL；若 RL 只能通过降低实际速度换取误差改善，停止声称无条件性能提升。
- [ ] 预先注册安全表述：没有误差界、终端安全集和可执行备份策略时，只能使用“经验可行性筛选”，不能写“形式安全保证”。

### 0.3 目录和实验身份

- [ ] 建立 `experiments/h15_mainline/`，禁止把新结果混入旧输出目录。

## 2. 阶段 B：先修计算底座和状态约束

目标：在引入学习方法之前，消除可以由确定性工程直接解释的失败。

### B1_solver. 求解器结构复用

- [ ] 测量当前每周期重新创建 OSQP 的 setup、solve、植物积分和日志写入耗时。
- [ ] 固定稀疏矩阵结构，只更新数值项，比较 setup 时间与 solve 时间。
- [ ] 启用真正的 solver warm start，并记录初始残差、迭代数和最终状态。
- [ ] 对 Hessian、线性项和状态尺度做数值缩放试验，确保缩放不改变任务代价含义。
- [ ] 设置受控迭代上限和超时行为；超时不能直接复用未检查的旧命令。
- [ ] 对接受解增加有限性、残差、命令边界和预测状态检查。
- [ ] 明确实现分支：RTI 的路径/状态约束与 condensed QP 的命令盒约束分别记录；`CondensedActuatorMPC` 不能单独承担 H15 的速度、姿态和走廊约束。
- [ ] 对 condensed 实现记录每个 batch item 的 OSQP 重建尾延迟，并与固定稀疏结构的 warm-start 版本做同硬件比较。
- [ ] 候选速度筛选不得默认对每个候选完整重跑一次 MPC；若采用枚举，必须把候选数、总耗时和最坏尾延迟纳入预算。
- [ ] 将所有求解器改动与控制性能改动分开提交和分开比较。

### B2_constraints. 实际执行器与状态约束

- [ ] 将实际执行器状态和待执行命令队列纳入预测约束检查。
- [ ] 对预测的实际航速、横向、深度和俯仰增加约束或可解释的安全余量。
- [ ] 明确输入变化率约束，避免只限制发出命令的幅值。
- [ ] 在每个 0.02 s 子步检查真实植物状态；记录预测违约与真实违约的对应关系。
- [ ] 为 QP 不可行、超时和预测风险过高定义有限时长备份轨迹。
- [ ] 记录备份轨迹的触发原因、接管时长、实际约束结果和任务是否仍满足“无回退”标准。
- [ ] 不把奖励惩罚、动作 clipping 或“舵回中”单独称为安全过滤器。

### B3_base. 确定性底座评估

- [ ] 运行 `B1_solver`：`B0_hist` + solver 优化。
- [ ] 运行 `B2_constraints`：`B1_solver` + 状态/执行器约束。
- [ ] 运行 `B3_base`：`B2_constraints` + 有限时长备份/重规划。
- [ ] 按同一配对单元比较 `B0_hist`、`B1_solver`、`B2_constraints`、`B3_base` 的完成率、首次异常、回退、饱和和整周期耗时。
- [ ] 单独报告确定性底座带来的改善，不计为 RL 收益。
- [ ] 若状态约束使回退显著增加，先调整可行性管理，不进入 RL 训练。

**阶段门 Gate2：**

- [ ] `B2_constraints`/`B3_base` 的状态和执行器约束已经在日志中可解释。
- [ ] solver 优化后的整周期 p99 有可测余量；若没有，暂停后续在线候选集设计。
- [ ] 备份接管和任务失败的口径已经固定。
- [ ] 至少一个确定性版本在开发集上稳定运行，且没有通过放宽 H15 判据取得收益。

## 3. 阶段 C：建立历史响应估计器

目标：估计可部署的等效响应，不把仿真隐藏参数或未来扰动泄漏给控制器。

### C1. 数据生成与可辨识性检查

- [ ] 从训练几何和训练植物/扰动种子生成状态、命令、实际执行器和响应残差历史。
- [ ] 实现历史缓冲区、回合 reset 和 burn-in 语义；记录窗口内实际执行器、排队/已发命令、状态误差、MPC 计划和时间戳。
- [ ] 将历史窗口长度设为可比较的候选值，例如 0.5 s、1.0 s、2.0 s，并写入配置。
- [ ] 检查历史中是否存在足够的舵角/推力激励；低激励窗口标记为不可辨识，而不是强行输出精确参数。
- [ ] 将二阶执行器速率、命令延迟、舵效、海流估计和动力学残差分成不同预测目标。
- [ ] 训练数据只包含部署可得字段；删除真实随机舵效、未来海流和未来扰动真值。
- [ ] 保存每个训练样本的路径族、植物族、扰动族、时间段和数据哈希。
- [ ] 按 `path × plant × disturbance` 家族切分 train/validation/test；归一化均值、方差和缺失值策略只在 train 拟合并冻结。
- [ ] 定义估计器输出为“点估计 + 半径/区间”，预先声明名义覆盖率（例如 90%）和区间宽度指标。
- [ ] 定义低激励、分布外、历史不足、NaN 和过期输出的行为：标记 OOD、扩大区间并回退到 E0，不能静默使用上一次精确参数。

### C2. 估计器对照

- [ ] E0：固定保守预测 `.85/2.0`。
- [ ] E1：有界 RLS/EKF 或移动窗估计，输出点估计和误差包络。
- [ ] E2：历史窗口监督模型，输出时域等效参数和校准不确定度。
- [ ] E3：HyperMPC 风格的历史 + 上一轮计划动作条件模型，输出全预测窗等效参数。
- [ ] 对 HyperMPC 风格参数只使用“时域等效参数”表述；不得把它直接解释为真实舵效或物理时间常数。
- [ ] 对每个估计器限制输出范围、变化率和数值异常处理。
- [ ] 估计器异常时回退到 E0，并单独计数回退。
- [ ] 测量估计器前向、校准和回退耗时；过期、NaN 或超预算时的回退必须可重放。
- [ ] 仅依据验证集选择一个 `E_selected`（E1/E2/E3 之一），在进入最终公平链前冻结其 checkpoint、区间校准和归一化统计；不能让不同方法各自挑估计器。

### C3. 预测质量与控制相关性

- [ ] 在未参与训练的开发几何上测量 1、5、25 步状态/速度/位置预测误差。
- [ ] 对不确定度报告覆盖率、区间宽度和条件覆盖率，不能只报均方误差。
- [ ] 在 1/5/25 步和不同 OOD 分层上分别报告经验覆盖率、区间宽度与校准误差，不能把训练内覆盖率当作部署证据。
- [ ] 按耦合几何、舵效失配、执行器延迟、海流和噪声分层报告。
- [ ] 将预测器输出接入相同 MPC，比较严格完成率、假可行、假拒绝、饱和和耗时。
- [ ] 检查估计器是否只是让模型更保守；若完成率不改善，保留预测质量结果但停止控制收益叙述。

**阶段门 Gate3：**

- [ ] 估计器仅使用部署可得观测。
- [ ] 估计误差和不确定度在留出集上有校准证据。
- [ ] 至少一个估计器相对 E0 在控制相关指标上有可解释收益，或明确记录“模型估计没有转化为控制收益”。
- [ ] 估计器加入后的整周期 p99 仍未超过任务预算；否则转为离线诊断，不进入在线主线。

## 4. 阶段 D：构造确定性可行参考进度速度治理器

目标：先证明候选速度集合有判别力，再讨论 RL 选择。

### D1. 参考坐标契约

- [ ] 定义 `v_progress` 为几何路径弧长的参考进度率。
- [ ] 定义 H15 实际速度指标为沿路径切向的艇体对水速度相对 15 m/s 的误差。
- [ ] 明确植物位置导数中的海流项，以及参考位置/参考速度的海流补偿方式。
- [ ] 让 `_reference()` 和终点延拓使用同一个未来弧长计划。
- [ ] 对变速治理改用弧长/积分参考计划生成终点延拓；不能继续用固定时间偏移和采样路径速度拼接一个假定 15 m/s 的终点。
- [ ] 将估计器输出安全地接入 `observed_augmented_state`/预测模型，保持 22 状态队列、实际执行器语义和历史命令顺序不变。
- [ ] 分别实现并记录受约束 RTI 与 condensed 候选检查的 warm-start、约束和计时口径，不能把两种求解器的结果混成一个方法。
- [ ] 用固定 15 m/s 运行逐轨迹零动作回归，确认整理坐标契约没有隐含改变 `B0_hist`；在零流条件下断言旧参考数组与新固定 15 m/s 参考数组一致。

### D2. 速度意图与斜坡计划

- [ ] 定义动作 `a_k ∈ [-1, 1]`，映射到 `v_des = 15 + 2 a_k`。
- [ ] 在实现中将该动作明确命名为参考进度率意图 `nu_ref = ds_ref/dt`；由 `nu_ref` 生成水速/海流补偿后的 MPC 目标，H15 实际切向对水速度仍独立相对 15 m/s 判定。
- [ ] 每 0.5–1.0 s 更新一次意图，0.1 s MPC 周期内保持上一意图或按确定性斜坡平滑。
- [ ] 实现绑定当前动作的确定性计划 `v_progress[j] = Phi(v_des, v_progress[j-1])`，每个周期变化不超过 0.05 m/s；不能只检查“存在某个自由参考”而把所有动作误判为可行。
- [ ] 将首步变化率也纳入限制，不能只限制计划内部的后续节点。
- [ ] 保持参考进度率在 13–17 m/s；实际 H15 速度仍相对原15 m/s检查。
- [ ] 对每个候选意图生成完整的进度、位置、速度和终点延拓参考。

### D3. 候选计划筛选

- [ ] 初始用离线候选网格，例如 13.0–17.0 m/s，步长写入 manifest，不在测试时临时调整。
- [ ] 对每个候选意图运行相同的 MPC 和非线性延续检查；部署候选数固定为 manifest 中的 `K`，用 warm-start 或有界 surrogate rollout，禁止无限离线枚举冒充在线预算。
- [ ] 检查预测的实际执行器/命令队列、命令变化率、切向速度、横向、深度、俯仰和终端余量。
- [ ] 对 E1/E2/E3 的参数不确定度或扰动场景做明确的最坏/分位检查。
- [ ] 用不确定度对状态、执行器和终端约束做预先声明的收紧；记录每个候选被拒绝的首个原因、收紧量、slack 和筛选耗时。
- [ ] 保留不连通的候选段，不强行压缩成一个 `[v_min, v_max]`。
- [ ] 候选集为空时触发预定义保守逻辑、备份轨迹或任务重规划，并记录为空原因、接管时长和恢复条件；空集行为本身不能被隐藏在 clipping 中。
- [ ] 明确终端/备份判据：若没有满足终端余量的候选，输出受限备份或记为严格失败，不能把软 QP slack 当作物理可行。
- [ ] 对候选选择、过滤、备份激活、slack、fallback 和真实物理违约逐周期记录；任何物理违约或未定义 fallback 都计入严格失败。
- [ ] 不把一次 QP 可解、一次轨迹重放或 clipping 直接称为安全证明。

### D4. 候选集校准

- [ ] 预先固定一个延续控制器和重放时域，用于定义经验“可行/违约”。
- [ ] 计算“预测可行但该延续控制器重放违约”的条件比例。
- [ ] 计算“被筛掉但该延续控制器重放成功”的相对经验误拒比例。
- [ ] 明确这些比例只相对于指定延续控制器，不等于真实可行域的精确假拒绝率。
- [ ] 统计集合为空频率、候选数、筛选耗时和不同几何/扰动族的分层结果。
- [ ] 使用训练外几何和植物/扰动族进行候选集校准。

### D5. 确定性速度选择基线

- [ ] Gov0：固定 15 m/s。
- [ ] Gov1：曲率/坡度确定性规则。
- [ ] Gov2：候选集内最快可行速度。
- [ ] Gov3：候选集内最小风险速度。
- [ ] Gov4：同信息、同预算的确定性短窗/长窗速度优化。
- [ ] 所有 Gov0–Gov4 使用相同的 MPC、约束、参考坐标、随机种子和实时计时。
- [ ] 确认 Gov2–Gov4 的改进不是通过放宽 H15 速度、走廊或回退定义取得。

**阶段门 Gate4：**

- [ ] 候选集对未来几何/执行器状态有判别力，而不是几乎总为空或几乎包含全部动作。
- [ ] Gov2/Gov3 相对 Gov0 的失败类型和改善机制可解释。
- [ ] 确定性速度选择器已经成为 RL 的主比较对象。
- [ ] 在线实现的筛选耗时和整周期 p99 仍在预算内；否则只保留离线机制结论。

## 5. 阶段 E：接入受限 RL（只开放一个动作）

目标：验证 RL 是否能利用跨多个控制周期的信息，在相同候选集合和相同预算下超过 Gov2/Gov3/Gov4。

### E1. 部署可得观测

- [ ] 观测包含相对路径误差、艇体速度/角速度、实际执行器、命令队列和近期命令—响应残差。
- [ ] 观测包含前方曲率、深度坡度、距离走廊/姿态边界的余量和 QP 状态。
- [ ] 观测包含估计器点估计、不确定度和候选集摘要，而不是隐藏目标参数。
- [ ] 删除目标域真实舵效、未来随机噪声、未来海流真值和 oracle 可行性标签。
- [ ] 为观测字段写部署来源和单位，避免训练脚本直接读取仿真器内部变量。
- [ ] 记录观测归一化统计，只用训练集估计并冻结到验证/测试。

### E2. 动作、过滤与回退

- [ ] 策略只输出一个标量速度意图，不输出推力、升降舵或方向舵残差。
- [ ] 策略每 5–10 个 MPC 周期运行一次；MPC 仍每 0.1 s 求解。
- [ ] 动作经过 `v_des` 范围限制、斜坡限制和候选集过滤。
- [ ] 过滤失败或候选集为空时执行预先定义的确定性保守逻辑。
- [ ] 记录原始动作、过滤后动作、候选集状态、保守接管和实际参考进度率。
- [ ] 过滤后的动作不被重新定义为“安全动作”；安全结果由闭环指标判定。

### E3. H15 奖励与终止

- [ ] `strict_mainline` 全程完成作为唯一评估成功条件；训练时的提前终止必须保留原因，不能改变评估成功分母。
- [ ] 俯仰、航速、横向、深度、QP回退、备份接管和 deadline miss 分别记录。
- [ ] 奖励同时体现路径误差、原15 m/s速度误差、进度/用时、执行器饱和和动作抖动。
- [ ] 对持续降速设置明确代价，避免策略通过慢行取巧。
- [ ] 不用原环境宽松 `success`/`failed` 替代 H15 严格成功。
- [ ] 奖励权重、折扣、动作更新频率和终止条件在训练前冻结。
- [ ] 训练可为学习效率提前终止，但必须记录终止原因；评估始终保存完整尝试轨迹、首次违约和固定最大时域，不能用截断掩盖失败或改变成功分母。

### E4. 训练与选择

- [ ] 训练随机化艇体参数、舵效、执行器延迟、海流和过程噪声，但不改变 H15 任务合同。
- [ ] 训练几何与验证几何按家族隔离；验证只用于选择超参数和早停。
- [ ] 至少使用 3–5 个独立训练种子。
- [ ] 不用最终测试集选择 checkpoint、奖励权重、动作范围或候选筛选阈值。
- [ ] 只按验证集选择 checkpoint，并在测试前冻结；保留每个训练种子的代码哈希、配置、数据哈希、归一化统计、曲线、checkpoint SHA 和选择理由，测试数据哈希不得与训练样本重叠。
- [ ] 训练期间同步运行 Gov2/Gov3/Gov4 确定性参考，防止只看 reward 判断进步。

**阶段门 Gate5：**

- [ ] RL 只使用部署可得信息。
- [ ] 过滤/约束/回退行为可从日志重放。
- [ ] 至少一个独立训练种子在验证集上超过最强确定性 Gov3/Gov4，或达到相对其预先定义的 Pareto 改善候选；固定 15 m/s 只作 smoke sanity，不把验证结果当最终结论。
- [ ] 推理和过滤加入后的整周期 p99 仍可测量；超预算则停止在线主线。

## 6. 阶段 F：冻结策略并运行最终留出

### F1. 最终留出设计

- [ ] 生成未用于训练和调参的新耦合几何族。
- [ ] 生成未见的艇体/舵效/执行器参数族。
- [ ] 生成未见的稳态、非平稳和间歇海流族。
- [ ] 每个测试单元固定路径、植物和扰动种子，供所有方法配对使用。
- [ ] 建议初始设计为至少 8 个未见耦合几何实例、每个实例 20 个配对植物/扰动种子；正式样本量、最小置信区间宽度和资源预算必须在看测试结果前冻结，不能事后改 N。
- [ ] 旧修复留出不再用于调参后的盲测，只作为历史机制对照。
- [ ] 测试 manifest 生成后只读，写入 SHA-256。

### F2. 冻结方法清单

- [ ] 将第 B 节的 `B1_solver`/`B2_constraints`/`B3_base` 视为工程底座版本；最终公平比较链使用独立且无歧义的标签：`B0_shared`（`B3_base` + E0 保守估计、固定 15 m/s 意图、走同一过滤/备份链）、`B1_est`（`B3_base` + 冻结的 `E_selected`，仍使用固定 15 m/s 意图）、`B2_gov`（`B1_est` + 确定性速度治理）、`B3_RL`（`B2_gov` + 受限 RL 单一速度意图）。`B0_hist` 只作为旧 N35 可复现历史对照。
- [ ] 公平链所有方法使用同一路径/植物/扰动/种子、同一部署观测、同一状态/执行器约束、同一候选网格、同一筛选算法、候选数 `K` 和同一计算预算；只有 `B2_gov` 与 `B3_RL` 共享冻结的 `E_selected` 和每周期可行候选集，`B0_shared`/`B1_est` 的集合变化作为估计器消融报告。
- [ ] 为 `B3_RL` 建立经过同一过滤链的固定 15 m/s 意图分支；若该意图被拒绝，使用共同保守回退并按 `strict_mainline` 计分，不能声称实际速度始终固定 15 m/s。
- [ ] `B0_hist`：固定保守 N35 的历史重建控制；`B0_shared`：公平链中经同一估计/过滤/备份链的固定 15 m/s 分支。
- [ ] `B1_est`：`B3_base` + 冻结的 `E_selected`，固定 15 m/s 意图。
- [ ] `B2_gov`：`B1_est` + 候选集内确定性速度治理；分别报告最快可行（Gov2）、最小风险（Gov3）和同预算短窗/长窗优化（Gov4）。
- [ ] `B3_RL`：`B2_gov` + 受限 RL 单速度意图；“P”只作为旧日志兼容别名，不再单独作为比较方法。
- [ ] `U`：超在线预算长窗/离线 oracle，只作为诊断上界，不计入可部署比较。
- [ ] 将 U 明确标为不可部署的目标参数/可行性 oracle 上界，不能混入部署方法的平均值或主结论。

### F3. 配对运行与数据完整性

- [ ] 所有方法使用同一测试 manifest、同一随机种子、同一硬件设置和同一线程数。
- [ ] 运行前记录 git commit、环境版本、CPU、线程、求解器版本和配置哈希。
- [ ] 运行中禁止并行训练、自动调参和未记录的重试。
- [ ] 每个单元保存逐周期轨迹、方法摘要和异常日志。
- [ ] 运行后校验轨迹数量、路径/种子配对、文件哈希和完成状态。
- [ ] 对任何缺失、超时或损坏单元标记为缺失，不静默删除。

## 7. 阶段 G：统计、消融与机制归因

### G1. 主要结果

- [ ] 报告每种方法严格全程完成率和 95% 置信区间。
- [ ] 同时报告 `strict_hist`、`strict_substep_success` 和 `strict_mainline_success`；主结论使用 `strict_mainline`，14/20 只用于历史复现，不能混合分母。
- [ ] 报告逐单元改善数、恶化数、平局数及配对差异。
- [ ] 报告首次违约类型：俯仰、航速、横向、深度、求解、回退、候选为空、deadline miss。
- [ ] 报告切向对水速度误差、实际速度模长、完成时间、进度、饱和和能耗代理。
- [ ] 共同严格成功回合才比较位置/深度/航速 RMSE，并报告分母。
- [ ] 报告完整周期 p50/p95/p99、最大值、超100ms比例和发生超时的状态分布。
- [ ] 对几何族、参数族和扰动族分层，不能只给一个总平均数。
- [ ] 用回合/几何族作为配对单位做 bootstrap 置信区间；完成率同时给 Wilson 或 Beta 区间，并用配对置换/符号检验分析 discordant pairs。
- [ ] 预先冻结筛选样本量和资源预算（例如开发筛选 4 个几何族 × 5 个种子，最终至少 4 个新几何族 × 10 个配对种子；若沿用 20 个留出单元必须在 manifest 中写明理由）。

### G2. 必做消融

- [ ] 去掉历史响应输入，保留当前状态和命令队列。
- [ ] 去掉不确定度，只保留点估计。
- [ ] 去掉前方几何，只保留局部状态。
- [ ] 去掉候选集过滤，作为不安全机制对照并完整计入违约。
- [ ] 用确定性 Gov3/Gov4 替换 RL，保持完全相同输入和预算。
- [ ] 将 HyperMPC 风格时变等效参数替换为固定 `.85/2.0`。
- [ ] 将“点估计 + 区间”替换为“点估计-only”，保持网络容量、训练步数和候选/过滤链相同，以隔离不确定度治理的独立贡献。
- [ ] 将状态/执行器约束替换为仅命令盒约束。
- [ ] 将一阶执行器预测替换为二阶目标执行器重放，分离模型结构影响。
- [ ] 将固定海流替换为非平稳海流，检查预测器是否真的使用扰动历史。

### G3. 机制检查

- [ ] 在局部曲率相同但后续反向机动不同的配对状态上，检查策略是否提前作出不同速度选择。
- [ ] 在命令队列相同但响应残差不同的状态上，检查策略是否改变保守程度。
- [ ] 检查 RL 的改善是否只出现在候选集更宽或实际速度更低的单元。
- [ ] 检查移除历史/窗外几何后改善是否消失。
- [ ] 检查确定性估计是否已经解释全部收益；若是，RL不应被写为必要组件。
- [ ] 检查候选集为空是否集中在物理不可行、估计失配或求解预算不足的样本。

### G4. 统计解释

- [ ] 以几何族作为聚类单位或分层重采样单位，不能把每个0.1 s周期当独立样本。
- [ ] 报告点估计、置信区间和样本量，不用少量回合的平均 reward 代替完成率。
- [ ] 若未达到10个百分点实用阈值，明确写“未显示足够增益”，不通过调展示口径弥补。
- [ ] 若 RL 与 Gov4 完成率相同但速度/饱和有交换，报告 Pareto 权衡，不写全面优越。
- [ ] 若只有 `B1_est`/`B2_gov` 改善，结论写成确定性 MPC/可行性管理收益。

## 8. 阶段 H：实时性、鲁棒性和迁移复核

### H1. 完整周期计时

- [ ] 无并行竞争地测量观测构造、估计器、策略、候选过滤、参考生成、MPC 和植物积分。
- [ ] 单独标记策略触发周期、候选集为空周期和求解器重建周期。
- [ ] 重复多次运行并报告机器负载、线程和版本。
- [ ] 报告 p50、p95、p99、最大值和超100ms比例。
- [ ] 除报告超 100 ms 比例外，单独检查工程余量门：完整周期 p99 ≤90 ms、最大值 ≤100 ms、策略/估计器/过滤总开销 ≤5 ms；任一未满足都不得声称在线实时达标。
- [ ] 对所有新增模块的时间预算做加和审计，不用单独网络推理时间替代端到端时间。

### H2. 失败安全与恢复

- [ ] 注入求解超时、NaN、观测缺失、执行器传感器延迟和候选集为空。
- [ ] 检查每种异常是否有明确状态转移和有限时长恢复。
- [ ] 检查恢复期间是否记录为回退，并按 H15 严格定义计分。
- [ ] 检查恢复逻辑是否可能重复触发并导致速度或姿态失控。
- [ ] 检查恢复后重新进入候选集的条件是否可验证和可重放。

### H3. 迁移边界

- [ ] 在独立动力学实现或硬件在环前，不使用“独立 sim2sim”或“实艇泛化”表述。
- [ ] 明确 `h15_target_domain.py` 与名义环境仍共享方程结构（舵效缩放、积分器和二阶执行器应激）；该结果只能称“同方程参数应激 sim2sim”，不能称独立仿真迁移证据。
- [ ] 核对质量、阻尼、恢复力、舵效、执行器和推力功率模型的可追溯性。
- [ ] 将18 m/s压力实验与H15 15 m/s主任务分开，不混合完成率。
- [ ] 将低速 L6 作为单独适用范围实验，不用其结果证明高速主线。
- [ ] 只在模型参数、误差界和备份条件实际满足时讨论安全定理；否则使用经验风险描述。

## 9. 阶段 I：最终结论与停止条件

### I1. 可以继续 RL 主线的条件

- [ ] 候选速度治理器在留出上有稳定判别力，且不是几乎总为空。
- [ ] `B3_RL` 相对 Gov4 在相同信息、约束、候选集、训练/调参协议和实时预算下取得可重复的严格完成率改善，或预先定义的误差—时间—饱和 Pareto 改善。
- [ ] 改善不主要来自降低实际航速、放宽约束或增加回退容忍度。
- [ ] 新几何、参数和扰动族上仍能观察到改善。
- [ ] 完整周期 p99 和超时比例满足冻结的 H15 预算。
- [ ] 消融显示收益依赖跨周期历史/未来几何或不确定度信息，而不是仅来自 MPC 代码修复。

### I2. 应停止或转向确定性路线的条件

- [ ] `B1_est`/`B2_gov`/Gov3 已达到与 `B3_RL` 相同的性能；保留确定性成果，不强行加入 RL。
- [ ] 候选集大部分时间为空；先检查任务可行性、估计器覆盖和路径设计。
- [ ] RL 只通过明显降速改善误差；转向速度—精度—时间的明确多目标优化。
- [ ] RL 在验证集好、最终留出差；检查分布偏移和信息泄漏，不增加训练轮次掩盖问题。
- [ ] 新模块使整周期 p99 超过预算；先做数值/结构优化，暂停在线 RL。
- [ ] 状态约束和备份逻辑无法闭合；不把奖励惩罚包装成安全保证。
