## 算法思想与最小实现

主线为：**固定混合 MPC + 共享因果估计器 + 四维 PPO 信任门控**。失配分析决定固定采用“二阶推进、一阶双舵”；SVD结果决定按纵向、升沉、横向分配补偿信任，并将低中频深度代价与高频速度收益作为同时检验的目标。

第一版只学习“何时相信哪个补偿”，不直接输出舵角，不调整速度，不同时学习预测器。历史先显式堆叠进小型MLP，不做RNN/Transformer；残差先用因果EMA，不先训练新的神经预测器。这使第一次闭环比较尽快出现。

| 项目 | 首轮固定定义 |
| --- | --- |
| 频率 | 植物 .02 s子步；MPC .1 s；门控 .5 s；N=35 |
| 控制骨架 | 复用 `gs12_followup/hybrid_controller.py`；固定推力τ、二阶结构和因果推力速率观测器 |
| 策略动作 | `alpha=[a_theta,a_u,a_vertical,a_lateral]`，各在[0,1]；每次正常更新变化≤.25 |
| 参数门控 | `theta=[gain,tau_scale]=[.85,2]+a_theta*(theta_hat-[.85,2])`；初版仍是共同舵参数，非七种物理参数辨识 |
| 残差门控 | 对 `[u_dot,v_dot,w_dot,q_dot,r_dot]` 使用 `[a_u,a_lateral,a_vertical,a_vertical,a_lateral]` |
| 策略网络 | actor/critic各两层64单元Tanh；actor四维Gaussian，sigmoid后限速；PPO概率在原始Gaussian动作上计算 |
| 状态与历史 | 最近10个 .1 s测量帧 + 当前估计质量/门控/余量/已知参考预览；历史不足用首帧填充并给有效长度 |
| 共享模块 | 固定模型结构、估计器算法、归一化、残差滤波和补偿开关；在线估计状态仍因各自闭环数据而更新 |
| 首轮传感假设 | .1 s可读艇体状态和实际执行器；内部 .02 s真值仅用于评估。这个理想测量实验不等于实艇验证 |
| 初始条件 | 同一场景各方法相同状态、名义配平、命令队列、模型计划与参考；回合间清空所有历史/EMA/门控 |
| 任务 | 固定外生时间参考；沿用位置/速度/姿态解析一致生成；FSP与额外低层补偿关闭 |

估计器复用现有窗口舵响应拟合，窗口先用1 s；估计范围显式固定为gain [.7,1.2]、τ倍率[.5,2.5]。范围是首轮工程选择，非置信区间；低激励时回退[.85,2]。植物的真实阶次、参数、延迟、隐藏执行器速率不得进入策略、残差标签选型或归一化。

残差使用相同估计状态和已发命令构造：以固定混合模型 `F_ref` 为基准，`d_ref=(nu_next-P_nu F_ref)/.1`，其中 `nu=[u,v,w,q,r]`。首版EMA采用最近10个完整转移的指数加权窗口，权重按新到旧为`.8^i/sum(.8^i)`。门控更新后，用本次theta在这些已完成转移上重放模型差，逐样本得到 `d_theta,i=d_ref,i-P_nu(F_theta-F_ref)_i/.1`，再按同一权重平均；不把滤波残差减单个瞬时模型差当作精确重基准。每.1 s滑窗更新，当前theta在.5 s内保持。只重放一步模型，不额外解MPC。所得残差按三组门控注入N35预测窗并保持常值；这是局部加速度近似，不声称正确描述任意候选输入。各通道在重基准之后裁剪到训练校准集绝对残差99分位的3倍；平移加速度尺度下限.01 m/s²、角加速度下限.001 rad/s²，记录裁剪率及裁剪前值。

实现上在控制器外完成参数与残差混合，再调用既有 `solve(alpha=[1,1],theta_hat=theta_used,d_hat=d_used)`，避免双重门控；采用混合原型的25维接口，不能把25维状态直接送进原22维类。每次门控更新后使用一致模型及Jacobian，预测窗内冻结门控。残差全开可能局部抵消参数门控，所以记录首命令/预测对门控的敏感度，并保留固定参数门控消融。

- [ ] **T7｜补完整频域与最小消融，解释收益来自哪里。**

  **脚本：** `frequency.py --mode confirm`，`run.py evaluate --ablation ...`。

  **频域：** 先在15 m/s组合植物用三个轴向多正弦+零激励，每条144 s=16 s过渡+两个64 s窗，七频点沿用旧协议。固定、规则与五个RL策略共7个方法，每方法主幅.006四条、半幅.003三条（复用该方法零激励），共49条。保存完整复响应、同频奇异值及全部非激励频率能量。若各轴激励触发不同门控/参数，拼接矩阵只能称“逐轴同频经验响应”，其σ用于诊断，不能冒充同一MIMO系统的FRF/BLA。固定门控但参数估计仍变化的组也遵循此限制；候选控制器条件FRF另跑“先适应后锁定”模式。

  **锁定实验：** 在固定的非零校准激励预运行16 s，随后锁定门控、theta与残差偏置；三轴和零激励各自从同一已记录锁定快照开始，之后再做144 s辨识。不能只冻结神经网络权重。此实验对每seed4条，共20条；用来解释选出的局部控制器，不替代动态运行性能。

  **消融分两档：** 先做无需重训的①门控在前4 s后固定，②参数门控固定0，五个seed在24条dev上重放。它们是推理干预，不能当公平最优训练基线。只有需要论文级模块归因时，再对所有五个seed各做③残差三门控绑为同一量（两动作重新训练），④取消历史堆叠（同信息类型、单帧重新训练），预算同为32,768，共增加10个训练。正式归因需冻结消融配置并评估；原test若已用于调整消融，则使用新留出集。首次算法验证不要求这些额外训练，结论可先限定为“组合策略收益”。

  **方向泛化：** 五策略和强基线用新相位、门控时钟偏移.1/.2/.3/.4 s与若干未训练频率重放；完整.5 s偏移等于一个周期，不能用来检验稳态时钟相位。18 m/s近重奇异值用敏感子空间多个方向。只在局部频域结果成立后谈局部模型解释，首轮不构造额外IMC证明。

## 场景与数据分布的具体要求

所有物理因子相对旧实验的 `MISMATCHED_PLANT`，不相对每种控制器重新定义。`prepare`保存实际参数、随机seed及参考系数；训练actor不可读取这些评估元数据。

因本次重点是快速算法检验，第一轮不叠加海流、测量噪声、漂移、丢包与未知测量延迟。通过T5之后可复用同一120场景增加有噪测量确认；若未做，只能得出理想测量、同水动力模型族内的结论。已有382条只可做开发参照，不进入新test。

## 观测与奖励：给实现者的精确约定

**观测首版200维，schema决定顺序。** 10帧×18维：归一化east/depth/VN误差3、沿程north位置误差1、pitch/q/r 3、实际执行器3、已发命令3、五维一步创新5，共180维。当前20维：theta_hat2、估计半径2、上一门控4、三通道执行器余量3、上周期QP成功与求解时间2、未来.5/1 s归一化参考变化6、历史有效比例1。执行器用仓库CONTROL_SCALE，角度用rad，角速度用rad/s；其余尺度从train_calibration冻结。估计半径只作质量特征，不能叫概率置信区间。网络输入必须包含上次门控，因执行动作经过限速。

沿程误差的归一化先用8 m；pitch用40°，q/r用1 rad/s；训练残差尺度单独保存。预览是所有方法共同可得的解析参考；无私有额外参考、植物ID和真参数。记录精确 `feature_names/units/scale/source/timestamp`，任何列变化使schema哈希改变并使旧checkpoint不兼容。

**奖励初值：** 快层代价率 `l=||[e_E/8,e_D/5,e_VN/2]||²+.25*(e_N/8)²+.1*(pitch/40°)²+.01*||delta_u_norm||²+.02*sat_fraction`，每 .1 s取 `r_fast=-.1*clip(l,0,50)`；慢层 `R=sum(r_fast)-.01*||delta_alpha||²`，门控变化只罚一次。失败末步若只执行部分子步，用实际经过的dt积分。参数只是首轮默认，训练中不根据test调权。

沿用诊断阈值：横向8 m、深度5 m、切向速度误差2 m/s、绝对pitch40°或非有限值。评价误差的VN与诊断切向速度必须分列，不能混用。首次越界即失败并保存触界子步。首轮训练按有限时域无折扣 `gamma_fast=gamma_slow=1`，减少早停收益混淆；慢层累计实际执行的最多5个快步reward。训练正常任务结束是真终止；仅batch切断为截断并bootstrap。若后续改用折扣，须按快步折扣累计并使用实际步数幂，不沿用固定5步到所有终止样本。

失败成本明确采用剩余任务时长的吸收成本：每秒 `c_fail=100`，另一次失败代价20；剩余时长按同一个首次触界子步时刻计算，正常有限误差stage cost上限截到50/s，避免提前退出因免去未来stage cost而得利。数值失败与物理越界分别记录。此人工代价只服务训练；选择/评估先看失败数，再看真实未截断物理误差，不用return掩盖失败。

QP失败仍记单独事件并执行现有明确回退；门控失效/NaN统一回退零，紧急回退可越过正常门控变化率但必须记录override。所有方法共享这项规则。每周期超过.1 s只记录deadline_miss，首轮不据离线仿真速度自动改变动作；因此计时结论只能叫实时可行性测量，不能叫已部署实时控制。

## 四个入口脚本的接口与交付契约

| 待实现入口 | 子命令/输入 | 必需行为 | 必需输出 |
| --- | --- | --- | --- |
| `run.py` | `prepare/smoke/collect/tune/evaluate`，config、split、method/checkpoint、out | 统一环境；按manifest重放；禁止test用于拟合；结果目录存在时核哈希再resume，不能默默覆盖 | 场景清单、schema、校准artifact、每回合三时间尺度日志、摘要、所选基线 |
| `train.py` | config、seed(s)、decisions、update-every、artifact-dir、out | 复用PPO核心但解除旧2动作/37维/H15/4000上限；每次更新用单一旧策略版本采样，checkpoint保存RNG；只读train/dev | 策略checkpoint、更新日志、训练回合、dev选型记录、总步数/墙钟 |
| `frequency.py` | `--mode pilot/confirm/locked`、方法列表、方向源、out | pilot单方向；confirm三轴+零；locked保存适应后快照；相同幅值/相位/预览/单位；频率从整数bin精确生成，不用正文舍入数值；提前失败不输出伪FRF | 原始轨迹、复H实部/虚部、σ/U/V、方向增益、非激励能量、幅值/窗口一致性 |
| `report.py` | run manifest、episode summaries、frequency outputs、stage | 校验缺失/重复case；按共同场景配对，失败/能力不足分层；训练seed整簇汇总 | Markdown、CSV、NPZ、图、可复核计数及交付清单 |

辅助模块 `model_bridge.py` 处理状态/四门控与混合预测器；`features.py`处理窗口估计、EMA、200维观测与奖励；`data_io.py`处理不可变manifest、时间戳和schema。它们是四入口共享实现，不另造重复runner。已有脚本复用点详见附件 `script_reuse_notes.md`。

建议CLI执行序列如下，**需完成上述入口后才可运行**：

```bash
python -m experiments.gs12_gate.run prepare --config config.json --out outputs/gs12_gate
python -m experiments.gs12_gate.run smoke --run outputs/gs12_gate
python -m experiments.gs12_gate.run collect --run outputs/gs12_gate --split train_calibration --episodes 32
python -m experiments.gs12_gate.train --run outputs/gs12_gate --seed 41001 --decisions 8192 --update-every 512
python -m experiments.gs12_gate.run tune --run outputs/gs12_gate --split dev_screen
python -m experiments.gs12_gate.run evaluate --run outputs/gs12_gate --split dev_quick --methods hybrid_zero,fixed_best,rule_best,ppo
python -m experiments.gs12_gate.frequency --run outputs/gs12_gate --mode pilot
python -m experiments.gs12_gate.report --run outputs/gs12_gate --stage pilot
```

`train`和`tune`可以由两个前台工作进程并行，资源上限记录到manifest；不要让后台孤立训练成为交付。首次结果应在T5给出，T6–T7按收益信号选择投入。

按全回合且未缓存估算，T1短检240次MPC、T2校准7,680次、T3训练40,960次、T4筛选21,120次、T5末端快评23,040次和方向检查4,800次，合计约97,840次MPC。中点只增评一个PPO候选时另加5,760次；实际运行数、缓存复用、终止均单独计数。确认阶段训练为819,200次MPC、120场景正式评估230,400次；这些是算法信号出现后的投入，不属于首轮前期检验。

## 数据收集：保留什么、以什么频率、如何防止结果失真

| 文件 | 粒度与必须字段 | 使用要求 |
| --- | --- | --- |
| `run_manifest.json` | 代码/研究依赖哈希、配置、环境版本、seed空间、算法/估计器/特征/标签版本、时间尺度、起止时间、硬件/进程数 | 不写本机绝对路径作为交付；记录相对路径与哈希；真实配置属于评估metadata |
| `cases.jsonl` | case_id、split、植物家族/数值/阶次、参考系数与相位、初态、噪声seed、source、capacity_limited | 场景级划分，禁止将同一轨迹滑窗跨split；split冲突直接报错 |
| `control.npz` | 每.1 s：t、测量/估计状态、actual actuator、issued/mpc command、队列、当前/预览参考、误差、theta_hat/theta_used、d_ref/d_used、alpha、创新、QP状态、模型/估计/策略/求解/总耗时 | 保存控制器真正使用的数据；浮点数组保留可重放精度；只有完整.1 s转移进入估计/残差标签，末步部分转移另记actual_dt与无效mask；禁止只存RMSE |
| `decisions.npz` | 每.5 s及不完整末步：observation、valid mask、raw_z、logprob、target/applied alpha、value、逐项reward、快步数、terminal/truncated、override、policy_version | raw_z/logprob不可由裁剪后alpha反推；记录next_observation/next_value供PPO复核 |
| `substeps.npz` | 每.02 s：t、评估真状态/输出、reference、实际执行器、已发命令、诊断量、各阈值超限与饱和标志 | 全部评估、频域、校准和失败训练回合保存；其余成功训练回合可不存完整真状态，但必须在线累计峰值、饱和时长和首次触界 |
| `episode.json` | case/method/train seed/checkpoint、期望与实际时长、完成/首次失败时刻与原因、未截断误差积分、峰值/饱和、QP/超时/回退、门控变化、数据路径与哈希 | 所有训练与评估回合都保存，失败不删除；终止后的缺失值不补成0 |
| `frequency.npz` + JSON | 频率、实际输入复谱、误差复谱、H/U/σ/V、分析窗、方向复向量、幅值、时钟相位、非激励能量、有效性标志 | 缺周期/触界/饱和时标无效或非线性工况；动态逐轴响应拼接不当成统一MIMO FRF/BLA或通用LTI |
| `updates.jsonl` | 每PPO更新：train seed、样本数、累计decision/control/substep数、loss/KL/entropy/梯度、checkpoint哈希与wall time | 所有训练seed与尝试均记录，不能只保留最优实验 |

配对RMSE使用**该场景所有比较方法共同存活时间前缀**；完整成功回合RMSE另列，并标共同前缀长度，极短前缀不作为成功证据。优先看失败率/首次越界，再比较误差与控制代价。SVD指向的低中频改善和速度方向保留单列，不仅报告一个全带峰值。

本计划压缩的是前置工作量，不是必要日志和公平比较。T1–T5即可形成第一份有意义的算法结果；只有出现收益才投入多seed、完整频域、重新训练消融与更复杂失配适应。
