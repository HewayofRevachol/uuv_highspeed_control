# H15 当前问题—文献方法对应报告

日期：2026-11-04。本文按**当前问题 → 文献中的方法 → H15 如何接入 → 怎样验证**重排上轮已核验文献，便于选择下一步实验。没有新增训练或闭环结果；“建议接入”均为本项目的迁移方案，不是论文已经解决 H15 的结论。文献编号 P01 等沿用上轮报告，本文末尾提供独立可用的题名、出处和链接。

**当前最合理的顺序是：模型响应估计、真实约束和计算预算先形成确定性底座，再检验 RL 的长期决策价值。** 第一个 RL 动作仍建议只选参考进度速度；不同时开放舵角残差、权重、模型和预瞄。

## 二、问题1：舵效和执行器响应失配，固定保守先验不够灵活

**当前证据。** 四条耦合路径的组件消融中，源域 N35 为29/40；只改变舵效为10/40，只改变二阶执行器为11/40，两者叠加为4/40。在另一组新修复留出上，固定预测舵效×0.85、时间常数×2.0使原 N35 从0/20升到14/20。两组实验不能混成一条改善曲线，但都说明模型响应失配值得优先处理。

| 对应论文 | 文献中实际采用的方法 | 转成 H15 的具体做法 |
| --- | --- | --- |
| **P06 HyperMPC，CoRL 2025** | 将状态/动作历史和上一轮 MPC 的计划动作输入网络，预测整个时域的时变参数；网络在优化开始前前向一次 | 用艇体响应、实际舵角、命令队列和上一轮计划，预测用于补偿未建模响应的时域等效参数，供22状态预测器使用；不将它们直接解释为真实舵效或物理时间常数 |
| **P04 RMA，RSS 2021** | 部署时以状态—动作历史推断行为相关 latent，帮助基础策略适应未知动力学 | 借鉴历史编码器，比较“只看当前状态”与“看近期命令—响应”的差异；首先可用监督学习估计器，不必先训练完整RL控制器 |
| **P13 鲁棒自适应 MPC，IJRNC 2021** | 用集合成员估计缩小参数不确定集合；集合用于鲁棒约束，点估计用于性能优化 | 同时维护参数估计和误差范围，区分“更准确的预测”与“更保守的约束”；作为没有RL的强对照 |

**方法属性与前提。** HyperMPC 是学习模型增强 MPC，不是 RL 控制策略。RMA 的 latent 不能直接解释为真实舵效或时间常数。P13 的保证依赖参数集合包含真值、嵌套更新、初始可行等条件；H15 的二阶执行器、海流与估计误差需要另行建模。训练时可使用仿真参数作监督标签，部署观测不得读取隐藏参数或未来扰动。

**接入位置。** 在 `ActuatorAwareEnv.observed_augmented_state()` 上游增加历史和估计模块，向 `simulator/rti_symbolic.py` 的预测动力学提供有界参数。二阶舵机可能需要舵速率等额外隐状态，不能预设调一个一阶时间常数就足够。

**首个实验。** 固定保守 N35、显式有界辨识、历史常参数网络、HyperMPC式时变参数网络使用相同 MPC 和约束。分别看1/5/25步预测误差、误差范围覆盖、严格完成率和尾部耗时。只有参数误差下降而闭环不改善，应报告“模型拟合改善”，不能称控制提升。

**RL 在这里的角色：后置。** 确定性估计之后若仍存在“保守程度与长期进度”的选择，才考虑让RL选择经检验的保守模板。不能让策略任意缩小误差集合来换取速度。

## 三、问题2：命令盒约束没有覆盖实际状态，临时回退不能恢复可行性

**当前证据。** 当前 condensed QP 主要约束发出的三维命令；延迟后的实际执行器、航速、俯仰和走廊并未完整闭合。另一套 RTI 的硬路径约束试验仍记录219次回退；软约束曾允许约157°的预测俯仰松弛。保守 N35 的6次首次失败仍覆盖俯仰、航速、深度和求解失败。换成保持命令或回中舵未修复既有回退回合。

| 对应论文 | 文献中实际采用的方法 | 转成 H15 的具体做法 |
| --- | --- | --- |
| **P11 Predictive Safety Filter，Automatica 2021** | 检查候选输入能否接上通向终端安全集的备份轨迹；必要时修改输入，并保留此前可行备份 | 在危险发生前检查候选参考对应的MPC命令计划；保存仍有效的有限时长备份，明确何时接管、何时需要重规划 |
| **P05 MPCC++，RSS 2024** | 将路径管道和终端可行轨迹纳入轮廓控制，并用数据残差改进预测 | 把H15横向/深度走廊、姿态和速度限制变成预测约束；研究保留终端机动余量，而非只惩罚当前跟踪误差 |
| **P16 AUV tube-MPC，Ocean Engineering 2024** | 名义轨迹外建立扰动误差管束，收紧输入和状态约束，同时用LOS重规划参考 | 用明确的扰动/模型误差界为走廊和姿态留余量；比较“仅加状态约束”与“加约束收紧/参考管理” |

**方法属性与前提。** 三者首先是确定性控制或安全层，不需要RL才能起作用。P11的保证依赖终端安全策略、误差条件和初始可行；部分结论为概率保证。P05在实飞实现中把管道硬约束软化。P16采用6维广义力/力矩输入，不能直接套用到H15三命令加队列模型；其NMPC对照还省略了输入速率约束。因此需要重新实现和公平比较，不能搬用论文的安全或速度结论。

**接入位置。** `aav_mpc/condensed_mpc.py` 增加预测状态与实际执行器检查；`simulator/batch_path_env.py` 增加0.02 s子步的H15阈值记录；`aav_mpc/diagnose.py` 单列违约、备份接管、重规划和求解失败。

**首个实验。** 配对比较原保守N35、增加状态约束、增加收紧/备份三个版本，统计首次违约、回退、可行备份可用率和整周期耗时。候选集为空需显式处理；简单裁剪不产生安全解。按原H15“无回退”成功定义，备份接管不能通过改名消失。

**RL 在这里的角色：选择偏好，不定义安全。** 策略可以在经过核验的候选计划中选择；奖励惩罚和策略输出后的限幅不能代替状态约束与备份条件。

## 四、问题3：参考推进与预瞄耦合，短时域如何利用更远的机动信息

**当前证据。** CSV终点截断已经通过切线延拓修复，不应再当未解决的创新点。但改变参考速度后必须维持这项修复。现有预瞄容易同时改变位置推进和追赶负担；小矩阵也未显示预测窗越长越好。N35仅表示3.5 s、名义约52.5 m前视，并不证明剩余失败都由短视造成。

| 对应论文 | 文献中实际采用的方法 | 转成 H15 的具体做法 |
| --- | --- | --- |
| **P05 MPCC++** | 将路径轮廓误差与沿路径进度一起优化，路径几何不等同于固定时间轨迹 | 先构建确定性的进度优化基线，分开“看多远”“推进多快”“末端如何延拓”，覆盖三维曲率和深度变化 |
| **P09 RL-guided MPC，JAS 2024** | SAC输出高层参考位置参数，低层MPC负责动力学跟踪 | 借分层接口，把H15策略压缩成一个参考进度速度意图，低层仍只由MPC产生推力/舵角 |
| **P10 TD-MPC，ICML 2022** | 短窗规划后接学习的终端价值，用长期回报弥补规划窗外信息 | 若短窗缺口经反事实实验确认，再以末端艇体/执行器状态和窗外几何预测长期代价；先验证价值校准再接入控制 |

**接入方案。** 第一版只让策略每0.5–1.0 s给一个速度意图；低层每0.1 s按不超过0.05 m/s的增量生成参考斜坡，保持13–17 m/s范围。候选筛选必须核验这条斜坡对应的MPC计划。`ScheduledReferenceEnv._reference()` 与 `EndpointExtensionMixin._reference()` 共用一条未来弧长计划，避免一个变速、另一个仍按15 m/s延拓。

**必须明确速度口径。** 现有参考中的进度率是沿几何路径的推进速度；植物位置导数含海流，而H15误差检查为沿路径切向的艇体对水速度相对原15 m/s的偏差。两者在有流时不同。本接入方案将13–17 m/s及0.5 m/s²限制施加于几何参考进度率，原H15切向对水速度评价保持独立。参考的速度/位置海流补偿需一致，不能修改评价目标去追随策略给出的新参考。

**首个实验。** 先比较固定参考、干净的预瞄规则、同预算的确定性进度优化；再比较同一过滤链上的RL速度意图。用局部曲率相似但后续反向机动不同的路径检验长期信息是否有用。终端价值另设实验，与人工终端项和同预算长窗/非均匀网格比较。

**边界。** P09的“robust”主要指训练时注入动作噪声；原文省略终端代价/集合，不能当鲁棒递归可行证明。P10不能补齐当前H15尾段价值在未见几何上失校准的问题。RL调参考和学习终端价值已有先例，潜在贡献必须落到H15特有机制及实证增量。

## 五、问题4：求解尾部时间已逼近100 ms，新方法可能来不及运行

**当前证据。** 保守N35串行计时的p95中位数为45.84 ms，最大回合p99为99.79 ms，离100 ms门槛仅0.21 ms。p99低于门槛不等于每周期达标，更不是最坏执行时间证明。当前求解器每周期重新创建OSQP；名义命令计划移位不等于跨周期复用求解器状态。

| 对应论文 | 可借用的计算组织方式 | 在 H15 中的行动与限制 |
| --- | --- | --- |
| **P15 RTI，SIAM JCO 2005** | 不在每周期把整个非线性优化求到完全收敛，而是有限迭代跟随当前解 | H15已采用RTI式流程，应进一步检查矩阵结构复用、真正的solver warm start、数值缩放、预算与接受解检查；“使用RTI”本身不是新改进 |
| **P06 HyperMPC** | 学习模型在优化器外一次前向，优化内部仍用基础动力学 | 比较“每个优化节点反复调用网络”和“窗前一次参数预测”的端到端成本；计划动作失配和预测精度仍须测量 |
| **P03 ACMPC，T-RO 2026** | 用可微短窗MPC连接长期学习目标；同时报告时域增长带来的训练/推理成本 | 可作短窗控制的结构参考；短窗平均时间不能证明H15 N35可满足100 ms。该文求解器只支持输入约束，不支持显式状态约束，接入前仍需解决速度、姿态和走廊限制 |

**首个实验。** 在冻结硬件、线程和无并行竞争条件下，逐步添加估计、策略、过滤和参考模块，统计完整周期p95/p99、最大值、超时比例以及触发策略的那些周期。有限迭代之后还须检查解是否可接受，超时需要有效备份。

**RL 在这里的角色：暂不承担计算调度。** 本方案的低频RL只减少策略推理次数，MPC仍以10 Hz求解。先改善确定性底座的尾部耗时；只有还有明确计算调度权衡时，再另立事件触发研究。不能默认每周期枚举多个完整N35求解仍能实时。

## 六、问题5：随机目标域中，失败究竟来自模型、扰动还是任务不可行

**当前证据。** 固定目标模型、无流无噪声的四条耦合路径已有全程合规命令，但完整随机扰动下的全程可行性未封闭。有限时间搜索没有找到解，不能证明无解。当前两域仍共享水动力方程，也不能称严格独立物理模型验证。

| 对应论文 | 可借用的方法 | H15 中对应的实验问题 |
| --- | --- | --- |
| **P01 Swift，Nature 2023** | 用目标平台观测/动力学残差改进仿真，再训练和部署；有实机验证 | 当前用目标域可观测残差校准预测，分别比较随机化、残差校准和在线适应；最终用独立动力学或硬件证据检查迁移 |
| **P08 AUV SSA–diffusion–MPC，TCYB 2026** | 当前扰动估计、趋势/残差分解、未来扰动预测、带宽/饱和过滤和MPC前馈 | 只有残差存在可利用的时间结构时，才比较预测器是否改善机动前的参考计划；先用持久值、AR/Kalman、谐波或小GRU作对照 |
| **P14 Learning MPC，TAC 2018** | 从同一任务的已成功轨迹构造采样安全集和终端成本 | 将确实可重放的成功轨迹用作诊断、候选备份和尾段标签；不能把一次失败的搜索结果标为“不可行”负样本 |

**方法属性与前提。** P01是RL系统，但目标域残差校准本身并非RL独有；特定赛道实飞不证明未见海况泛化。P08的diffusion模块是预测器，不是RL；本次仅核验摘要，不能移植其稳定性证明。P14依赖已有可行轨迹和相应模型/任务条件，新几何、随机海流不能直接继承其安全集。**这些论文均不能直接判定当前所有随机H15路径是否可行。**

**首个实验。** 在开发集分别开关模型失配、执行器变化、海流和噪声；对候选计划使用固定的延续控制器、时域和扰动种子重放。报告预测可行但重放违约的比例、集合为空频率、首次违约；重放失败与数学不可行分开记录。最终按新几何、新植物参数和新扰动家族分别留出，旧修复留出不再用于调参后“盲测”。

**RL 在这里的角色：利用经验证的信息。** 如果预测不确定度确实改变候选速度计划的可信程度，策略可据此作长期取舍；若简单预测器已经足够，就没有为diffusion付出训练和在线成本的理由。

## 七、问题6：如何证明收益来自 RL，而不是修好 MPC 或改变任务

**当前证据。** 旧18 m/s任务中的三版PPO未明确超过强确定性曲率规则；这些结果不能搬成H15结论。当前14/20的改善来自固定保守预测，已经说明不加RL也能获得很大收益。

| 对应论文 | 对研究设计的直接启发 | H15 应如何比较 |
| --- | --- | --- |
| **P02 Reaching the limit，Science Robotics 2023** | 将“用什么优化方法”与“优化什么目标”拆开；同跟踪目标下MPC不弱于RL，任务级目标会改变行为 | 保持H15任务、允许速度范围、未来几何、历史观测和计算预算一致；不把更宽松目标带来的收益记作RL优势 |
| **P09 RL-guided MPC** | 高层参考可由RL生成，低层控制仍保留模型优化 | 同一参考/过滤/MPC链上，只替换参考选择器：确定性速度优化与RL分别运行 |
| **P03 ACMPC** | 另一条路线是让RL学MPC的代价参数，而非直接舵角 | 若速度意图路线不足，再单独测试受限代价学习；不能与速度、模型、预瞄同时开放，否则无法归因 |

**最小对照链。**

1. 固定保守N35、固定15 m/s参考。
2. 增加在线估计与状态约束/备份，参考仍固定——衡量确定性底座收益。
3. 在同一候选集合上，用确定性规则或同预算短/长窗速度优化——衡量参考治理收益。
4. 保持第3步的信息、过滤、约束和预算，仅由单动作RL选择意图——衡量RL增量。

零动作策略应与**共享全部参考和过滤链的固定15 m/s意图分支**逐轨迹等价，不应要求它等于主动调速的确定性优化器。至少使用多个独立训练种子、新几何/植物/扰动配对单元；主指标为严格全程完成、改善/恶化数、首次违约和耗时。共同成功回合再比较误差、用时与饱和，并保留失败回合。H15配置中10个百分点是实用收益关注阈值，统计置信区间仍需单独报告。

若第3步已达到相同表现，应保留确定性成果；若第4步只通过降低速度换取精度，应报告明确的速度—精度交换，不能称全面提升。

## 八、建议实际拼接的最小方案

| 模块 | 借鉴来源 | 本轮研究中的职责 |
| --- | --- | --- |
| 历史响应估计 | P04 RMA、P06 HyperMPC；P13作为确定性对照 | 提供有效响应和可信范围，不直接控制舵角 |
| 状态约束和候选计划检查 | P11 PSF、P05 MPCC++、P16 tube-MPC | 检查给定参考斜坡实际产生的命令计划，维护备份与终端条件 |
| 确定性进度优化 | P05；并对照现有曲率规则 | 先建立强参考选择器，验证候选集本身是否有控制价值 |
| 单动作RL参考选择 | P09分层接口，P02约束公平比较 | 利用历史响应与后续机动做长期取舍；必须证明独立增量 |
| 整周期计算组织 | P15 RTI、P06优化器外预测 | 控制求解、估计、策略和过滤的总成本，不以网络单独耗时替代 |

先并行处理问题1、2、4及评价口径，再处理问题3的干净参考接口，最后按问题6检验RL；问题5的分布拆分和留出从一开始固定。TD-MPC终端价值与diffusion预测分别作为有条件的第二阶段模块，不在首个原型里全部叠加。

**评价前还需统一一个细节：**现有H15严格阈值主要按0.1 s周期日志审计，0.02 s积分子步只有宽松终止保护。新增子步严格检查后，所有基线一起重评，并保留原口径；不能用新口径结果直接声称超过历史14/20。
