# GS-18：固定 MPC 权重，只优化 β

目标是检验：在十状态指标 J10 下，最佳固定 β 是多少，动态 β 是否还有值得利用的取舍。

本方案取代原规划中“RL 没有胜出后调整 MPC 权重”的第二轮。此前姿态 ×128、位置 ×0.25 的结果保留为历史记录，不能用于归因 β 的收益。

## 固定条件

- MPC 位置、姿态、速度等所有目标权重均采用现有 GPU 控制器原值，倍率固定为 1。
- 植物、失配、初态、GPU CuSADi ADMM 配置沿用 GS-12。设置从冻结 checkpoint 同目录的 `run.json` 读取。
- β 目标范围仍为 [0, 0.75]，每 0.1 s 最大变化 0.02；RL 每 8 s 选择目标。
- 所有方法统一从 β=0.75 起步。旧结果的固定 β 从各自取值起步，所以只能参考旧结果，新比较统一重跑。
- J10、0.02–64 s 评分窗口、四组权重和归一化尺度沿用 `metrics.py`，任务等权取均值。
- 完成全部任务且无 QP 失败、命令饱和和执行器饱和的固定 β 才能参与选优。各状态 RMSE、峰值照常报告；东向位置 10 mm 退化容差已取消。

## 第一阶段：配对开发实验

使用现有 `tasks_dev.jsonl` 的 12 条任务，扫描 β=0、0.25、0.5、0.525、0.55、0.575、0.6、0.65、0.75，共 9 个固定值。现有 GS-12 RL 另跑一次作诊断，共 120 条闭环 episode。

先查看各任务的 β–J10 曲线，再按任务等权平均 J10 选择一个全局固定 β。比较它与 β=0.55，以及现有 RL 与最佳固定 β 的差异；不能只与 β=0 或 0.75 比较。

再汇总“每条任务各选一个固定 β”的理想分数及所选 β。此前约 0.38% 的差距只反映**任务间固定 β 选择**的收益空间，既不是动态 β 的严格上限，也不能证明随时间调整没有用。新结果会将此诊断与全局最优固定值并列报告。

若曲线仍平坦、任务间取舍很小且现有 RL 没有稳定优势，先以最佳固定 β 收尾。若存在清晰的跨任务取舍，或轨迹显示不同时间段有可解释的预测偏置需求，再设计动态 β 实验。不能为了得到改善而转去搜索 MPC 权重或修改 J10。

## 第二阶段：冻结固定 β，独立验证

开发结束生成 `selected.json`，冻结所选 β、基线 β=0.55、checkpoint、求解设置、公共初始 β、指标/控制代码、开发和验证任务摘要。验证入口核对冻结文件，直接使用已选 β，不在验证集重新扫描或排名。

新 `tasks_beta_validation_v3.jsonl` 预先固定 8 条任务：深度低/高频各一条、左右转向各一条、北向速度变化两条、耦合机动两条，均为 64 s、15 m/s 名义速度，尚未运行闭环。旧 4 条留出任务和 v2 的 8 条任务已揭盲，只能作历史复测。脚本预检会排除对开发和两组旧验证任务的原样复制；这不等于统计独立性的证明。

固定 β 候选相对 β=0.55 的验收条件为：平均 J10 至少下降 5%，全部任务完成且 QP 失败与饱和均为 0。同步报告逐任务胜负和十状态 RMSE 变化。5% 是工程门槛，8 条确定性任务不支持统计显著性结论。候选若仍是 β=0.55，就没有新固定值收益，可先保留新验证集，避免重复运行。

现有 RL 在验证中只作冻结对照，与**开发集选定的**最佳固定 β 比较；不根据验证结果改换 β 或继续调参。该 RL 仍使用旧三量奖励，本轮评估不代表它已按十状态重训。

## 条件满足后才开展动态 β 训练

若第一阶段给出明确动机，另立训练协议：动作只控制 β，MPC 原权重不变；奖励改为同一十状态分组代价，观测补足状态误差，训练和基线均使用同一 GPU 后端。先在训练/开发任务上用多个训练种子比较，再冻结策略，对照最佳固定 β 做独立验证。已查看的验证任务不得再称为新留出集。

本次补充的脚本覆盖固定 β 开发、现有 RL 配对诊断和冻结验证；尚未新增全状态 RL 训练实现，也未启动仿真。

## 运行方法

从仓库根目录执行。预检读取文件并校验协议，不创建结果目录、不运行 GPU 闭环。

```bash
python3 experiments/GS-18_full_state/beta_only.py develop --out outputs/gs18_beta_only_dev --dry-run
python3 experiments/GS-18_full_state/beta_only.py develop --out outputs/gs18_beta_only_dev
```

开发结果中的 `selected.json` 存在且决定进入验证后：

```bash
python3 experiments/GS-18_full_state/beta_only.py validate --selection outputs/gs18_beta_only_dev/selected.json --out outputs/gs18_beta_only_validation --dry-run
python3 experiments/GS-18_full_state/beta_only.py validate --selection outputs/gs18_beta_only_dev/selected.json --out outputs/gs18_beta_only_validation
```

两阶段分别使用新的空输出目录。`protocol.json` 保存协议与摘要，`summary.json` 保存方法均值、分项、选优/验收和对照，`REPORT.md` 提供简表；`episodes.jsonl`、`traces/` 保留逐任务指标和原始轨迹。无合格固定 β 时不生成 `selected.json`，先分析失败，不能用失败方法剩余轨迹的均值选优。
